01 Nível 0 — O que é DNS em termos simples?

DNS (Sistema de Nomes de Domínio) é como a lista telefônica gigante da internet. Ele ajuda seu navegador a encontrar o endereço real (IP) do site que você digita.

Imagine pedir ao seu navegador, seu assistente útil, para buscar uma página da web. Ele verifica um enorme diretório da Internet para encontrar o endereço exato desse site e depois o carrega.

Este processo de pesquisa geralmente segue um de dois caminhos:

  • Verificação rápida do cache — se você visitou o site recentemente, o navegador recupera o IP do cache, fazendo com que a página carregue quase instantaneamente.
  • Pesquisa completa de DNS — se não houver dados armazenados em cache, o navegador solicita a um resolvedor DNS que encontre o endereço IP consultando servidores DNS na web.
02 Estrutura do pacote DNS

Um pacote DNS é composto basicamente por um cabeçalho fixo e quatro seções principais: perguntas, respostas, autoridade e adicional.

1. Cabeçalho (Header) — 12 bytes

CampoTamanhoDescrição
ID16 bitsIdentificador da consulta, usado para casar resposta.
Flags16 bitsFlags que indicam tipo e opções da consulta.
QR1 bitQuery (0) ou Response (1).
Opcode4 bitsTipo de operação: normal=0, inversa=1, etc.
AA1 bitAutoritativo: servidor autoritário responde.
TC1 bitTruncado: setado se o pacote for maior que UDP.
RD1 bitRecursão desejada.
RA1 bitRecursão disponível.
Z3 bitsReservado, sempre 0.
RCODE4 bitsCódigo de resposta: 0=sucesso, >0 erro.
QDCOUNT16 bitsNúmero de entradas na seção de perguntas.
ANCOUNT16 bitsNúmero de registros na seção de respostas.
NSCOUNT16 bitsNúmero de registros na seção de autoridade.
ARCOUNT16 bitsNúmero de registros na seção adicional.

2. Seção de Perguntas (Question Section)

  • QName: nome do domínio consultado, codificado em labels, exemplo: 3www6google3com0.
  • QType: tipo de consulta, como A, MX, NS.
  • QClass: classe, normalmente IN para internet.

3. Seção de Resposta (Answer Section)

Registros que respondem a pergunta feita. Cada registro inclui Name, Type, Class, TTL, Data length e RDATA.

4. Seção de Autoridade (Authority Section) — contém registros que indicam servidores DNS autoritativos para o domínio.

5. Seção Adicional (Additional Section) — informações adicionais úteis, como IPs dos servidores autoritativos para agilizar consultas.

// Exemplo simplificado Se você fizer uma consulta para www.example.com tipo A: cabeçalho com ID e flags, pergunta para www.example.com, resposta com IP na seção Answer, e autoridade/adicional apontando para servidores DNS e IPs deles, se houver.
03 Nível 1 — Fluxo completo da resolução

Se o navegador encontrar o endereço IP no cache, no navegador ou no sistema operacional, ele o usará imediatamente.

Caso contrário, ele alcança um resolvedor de DNS, como o DNS do Google ou o DNS do seu ISP, para fazer a pesquisa:

  1. O resolvedor entra em contato com um servidor raiz. Para www.example.com, o servidor raiz aponta para o TLD .com.
  2. O servidor TLD .com diz ao resolvedor qual servidor autoritário sabe sobre example.com.
  3. O resolvedor consulta esse servidor autoritário, que retorna o endereço IP final.
  4. O resolvedor envia esse IP de volta ao navegador, que então busca o site.
04 Registros DNS, TTL, zonas e rDNS

Cada domínio é apoiado por registros DNS, armazenados em servidores confiáveis. Esses registros controlam como um domínio funciona.

RegistroUso
AMapeia um domínio para um endereço IPv4.
AAAAMapeia um domínio para um endereço IPv6.
CNAMEAponta um domínio para outro domínio, como alias.
MXInformações do servidor de e-mail para entrega de e-mail.
NSAponta para os servidores de nomes autorizados do domínio.
TXTUsado para verificação de domínio, SPF, etc.
SOAInformações administrativas sobre a zona DNS.
CAAEspecifica quais CAs podem emitir certificados SSL.
PTRHabilita DNS reverso: IP para domínio.
SRV / NAPTRUsado para VoIP e roteamento avançado de serviços.

TTL — Time to Live define por quanto tempo um registro DNS pode ser armazenado em cache antes de precisar ser atualizado. Se você atualizar um registro A para apontar o domínio para um novo host, pode definir um TTL baixo, como 300 segundos, temporariamente para que as alterações propaguem mais rápido.

Zonas e arquivos de zona guardam todos os registros DNS associados ao domínio. Ao atualizar registros no painel do provedor, como A ou CNAME, você modifica esse arquivo. As alterações entram em vigor quando o TTL expira e novas consultas são feitas.

DNS reverso (rDNS) mapeia endereços IP de volta para nomes de domínio. Ele ajuda em filtragem de spam por e-mail, legibilidade de logs, auditoria, diagnóstico e construção de confiança com serviços de terceiros.

05 Tipos de resolvedores DNS
  1. Resolver toco: vive no seu dispositivo, navegador ou SO, e encaminha consultas para um resolvedor completo.
  2. Recursive Resolver: faz a resolução completa consultando vários servidores upstream. Exemplos: Google DNS (8.8.8.8), Cloudflare (1.1.1.1) e resolvedores de ISP.
  3. Resolvedor Iterativo: usado entre servidores DNS. Responde com: "Não sei, mas experimente este servidor".
  4. Resolvedor de cache: armazena registros resolvidos anteriormente, reduz pesquisas repetidas e honra o TTL.
  5. Resolvedor Autoritário: fonte final da verdade; hospeda e serve registros DNS reais para um domínio.
06 DNS criptografado — DoH e DoT

As consultas DNS são não criptografadas por padrão, o que as torna vulneráveis a monitoramento por ISPs, governos e intermediários, além de sequestro ou spoofing por atacantes.

DNS sobre HTTPS (DoH)

  • Criptografa consultas DNS usando HTTPS padrão, porta 443.
  • É mais difícil de bloquear ou interceptar.
  • É usado por navegadores como Chrome e Firefox.
  • É suportado por Cloudflare e Google DNS.

DNS sobre TLS (DoT)

  • Criptografa consultas DNS por TLS, porta 853.
  • Funciona no nível do sistema operacional ou roteador.
  • É suportado por Android 9+, distros Linux e provedores de DNS de privacidade.

Ambos melhoram a privacidade e a integridade das comunicações DNS.

// DoH — DNS encrypted DoH coloca consultas DNS dentro de uma conexão HTTPS na porta 443, misturando-as com tráfego normal da web. Isso dificulta monitoramento por ISPs, bloqueios seletivos por firewalls e spoofing de DNS.
07 tcpdump, transferência de zona e AXFR

Para observar consultas DNS tradicionais na rede:

tcpdump — DNS porta 53
sudo tcpdump -i any port 53

Transferência de Zona DNS (Zone Transfer) é o mecanismo pelo qual um servidor DNS secundário obtém uma cópia completa dos registros DNS de um servidor primário.

  • Para que serve: manter vários servidores DNS com as mesmas informações, garantindo redundância, disponibilidade e sincronização.
  • Uso legítimo: replicação oficial e autorizada entre servidores DNS da mesma organização.
  • Uso malicioso: atacantes podem tentar obter AXFR sem autorização para enumerar registros DNS, subdomínios e detalhes de rede.

AXFR é o tipo de requisição DNS usado para pedir a transferência completa da zona de um domínio de um servidor DNS primário para outro. Em pentests, é usado para testar se um servidor está bloqueando corretamente transferências não autorizadas.

09 DNS em C2, stager e tunneling

DNS é um dos protocolos mais antigos e essenciais da internet. Quase todo ambiente permite consultas DNS, por isso ele pode ser abusado em comunicações de Command & Control (C2).

  • Baixa detecção: firewalls raramente bloqueiam DNS.
  • Tráfego normal: consultas DNS parecem legítimas, então tráfego malicioso pode tentar se misturar.
  • Infraestrutura simples: o atacante pode controlar um domínio e registrar respostas DNS sem manter um servidor web inteiro.

Stager + DNS

Stager é o primeiro payload. Ele geralmente é pequeno e tem o objetivo de comunicar com o C2 e baixar a carga principal em uma cadeia multi-stager.

  • Fazer uma consulta DNS para um domínio controlado pelo atacante.
  • Receber instruções dentro de uma resposta DNS, como TXT record.
  • Baixar o próximo estágio por HTTP, SMB ou continuar tudo via DNS.
// Exemplo didático Uma vítima infectada faz uma query a1b2c3.attacker.com. O servidor DNS do atacante responde com um TXT record contendo instruções ou conteúdo codificado.

DNS Tunneling permite comunicação bidirecional via DNS.

  • Exfiltração: dados sensíveis podem ser enviados em pedaços, codificados no nome da consulta, como senha123.attacker.com.
  • Comando: o servidor controlado responde com novos comandos.
  • Ferramentas comuns: iodine, dnscat2, dnstunnel.

Importante: isso é usado em Red Team para simular um atacante persistente e testar a capacidade de detecção da empresa.
